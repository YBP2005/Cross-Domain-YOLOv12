# A4b 计时模型：两系数重标定（2026-09-30，闭合 A4 登记的缺口）

> # ⛔ **本件的结论已被 `A4c_计时模型_用真实图数复核.md` 取代（同日）。**
>
> 本件的错误在于**前提**：它断言"图数只能从训练日志取，日志里没有 `val: Scanning` ⇒
> 两系数形式无法本地重拟合 ⇒ 建议不要报计时模型"。**但图数在数据集 yaml + 文件系统里**
> （`train:` / `val:` 两个相对路径，数目录即可）—— 取得机器只读访问后，A4c 走通了这条路，
> 并直接检验登记模型：**R² = 0.948**，`sfchd_20p_b` 精确命中。
>
> **仍然有效的**：§4.1「同一数据集内 s/ep 的**中位数**是稳健的 ETA 基准」。
> **作废的**：§4.2/§4.3 的"模型不可识别/不要报计时模型"。

> A4 登记的缺口是"**无 train/val 图数 ⇒ 两系数模型无法本地重拟合**"。
> 本件把它补齐：图数从**训练日志**的 `Scanning` 行提取，按 **dataset** 归位
> （不做"日志→run"归位 —— 日志名与 run 名不一致，且 A 机只有 266 个日志 / 804 个 run；
> 而计时模型本来就是按数据集标定的，两侧的键天然一致）。

### ★ 缺口没有完全闭合：**保留下来的日志里没有 `val: Scanning` 行**

实测：A 机 266 个日志 + B 机日志目录共 711 个 `.log`，`grep "val: Scanning"` **零命中**；
只有 `train: Scanning … : 100%% ━ M/M`。⇒ **val 图数在这批日志里根本不存在**，
因此**登记的两系数形式 `s/ep ≈ 2.727e-3·val + 4.85e-3·train` 依旧无法本地重拟合** ——
但原因被定位了：**不是"没解析"，而是"证据不在"**（要补 val 图数，只能从数据集的 data yaml 或
磁盘上的 `val/images` 计数取，两者都不在本次取件的 run 级产物里）。

**能做的**：用抽到的 **train 图数**标定**单系数**模型，并把 train 图数本身作为新资产登记。

## 3. 单系数重标定（**train 侧**，无截距）

| 形式 | 系数 | R² | 相对误差中位 | 最大相对误差 |
|---|---|---|---|---|
| `s/ep = c · train` | **c = 1.9299e-03** | -0.442 | 82.5% | 134.6% |

* 登记的旧模型里 **train 项系数是 `4.85e-3`** ⇒ 本次单系数拟合给 **1.9299e-03**（比值为 0.40×）。
  ⚠ 两者**不可直接比较**：旧模型是"val + train"两项之和，本式只有一项，
  且本式的样本只有 11 个数据集。**只能作为数量级核对，不能当作替换。**

### 3.2 与 A4 已更正的台账错误对照

* `gdut_hwd`：实测 **8.8 s/ep**（train 1389 图）⇒ 单系数模型给 2.7（0.30×）。
  A4 已更正台账：台账记 16–20 s/ep 并据此称"模型低估小数据集 2.2–2.7×"，真值 ≈8.8。
  ★ 本件给出**那处错误的机制**：若把 `gdut_hwd` 的 train 图数与**别的数据集**的图数搞混
  （或按图片目录而非实际 train split 计数），就会得到 16–20 的读数。真值 8.8。

## 4. ★★ 更重要的结论：**s/ep 根本不由数据集大小决定**

### 4.1 组内稳健、组间巨大 —— 但**与图数不成单调关系**

| 量 | 值 |
|---|---|
| 有 s/ep 记录、n≥5 的数据集 | 55 |
| 各数据集**中位** s/ep 的极差 | 25.5 ×（3.2 → 82.2） |
| 各数据集**内部** max/min 的中位 | **1.8 ×** ⇒ 中位数是稳健的 ETA 基准 |
| 各数据集**内部** max/min 的最大 | **36.0 ×**（`data`）⇒ 但**个别 run 可以被拖慢两个量级** |

⇒ 两条分开读：

* **中位数可用**：同一数据集内 s/ep 的中位离散只有 1.8× ⇒ 用中位数做 ETA 是稳的。
* **单系数模型不可用**：数据集之间的中位差达 25.5×，而这个差**不随 train 图数单调变化** ——
  同一族内就自相矛盾：`dota15_10p` **141 图 → 8.9 s/ep**、`dota15_20p` **282 图 → 7.9**、
  `dota15_50p` **705 图 → 13.4**（先降后升）；跨族更极端：`firesmoke_20p` **11232 图 → 64.4**
  而 `data` **23856 图 → 19.6**（图多 2 倍反而快 3 倍）。
* **个别 run 的离群不由数据解释**：组内 max/min 最高 36.0×（同一数据集、图数不变）⇒
  该差异只能来自**设备/调度**（同卡并发、batch 降级、OOM 回退），
  与 `通用经验与教训` #33「每卡只能有一个 trainer」同源。

### 4.2 单系数拟合失败的定量含义

| 事实 | 数值 |
|---|---|
| `s/ep = c·train` 的 R² | **-0.442**（负 ⇒ 比"直接用均值"还差）|
| 相对误差中位 / 最大 | 83% / 135% |
| 反例 | `dota15_10p` 141 图 ⇒ 8.9 s/ep；`firesmoke_20p` 11232 图 ⇒ 64.4 s/ep —— **小 80 倍的集反而慢 7 倍** |

### 4.3 对论文的建议

1. **不要报"计时模型"**。登记的 `s/ep ≈ 2.727e-3·val + 4.85e-3·train` 在本数据上
   **不可识别**：主方差来源（同卡并发）没有被固定，而它比数据规模大一个量级。
2. 改用**逐数据集的经验中位**做 ETA（A4 的表已经给了），并在稿中写明"**取中位不取均值**"
   （A4 已记录 `sgh_30ep_lr005_s43n` 的 26.9 s/ep 离群点）。
3. 若确要留模型式，须把**每卡单进程**作为前置条件写进协议，并给出该条件下的重标定 ——
   本次取件里没有"同数据集 × 同并发度"的对照 ⇒ 需要新实验（见云端清单）。

## 5. 与 A4 的关系

* A4 的**逐数据集 s/ep 表**（`analysis\A4_计时模型.md`）**不受本件影响** —— 那是直接从
  `results.csv` 末行 `time` 算的，不依赖日志；本件只是给那张表**加了 train 图数这一列**，
  并证明它**不是一个解释变量**。
* A4 已更正的台账错误仍然成立：`gdut_hwd` 实测 **≈8.8 s/ep**（台账写 16–20 是错的）。
  本件补充：其 train 图数为 **1389**；台账那个 16–20 的读数与任何"按图数换算"的口径都不自洽。

## 6. 新登记的两项资产 / 两项缺口

**资产**：

1. **train 图数表**（11 个数据集，见 §2）—— 从日志 `train: Scanning … : 100% ━ M/M` 抽取，可重跑。
2. **组内/组间离散的定量对照**（§4.1）—— 可直接用于稿中"为何不报计时模型"的一页。

**缺口**：

1. **val 图数不在保留的日志里**（711 个 `.log` 零命中 `val: Scanning`）⇒ 两系数形式仍不可本地重拟合；
   要补只能取数据集 data yaml 或 `val/images` 计数。
2. **缺"同数据集 × 同并发度"的对照批** ⇒ 无法把调度方差从数据方差里分出来（需新实验）。
