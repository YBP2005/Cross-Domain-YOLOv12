## 四、结局判读（写死，不许各自解释）

```
archive_snapshot  目录名含 .incomplete_<日期>  ⇒ 中断件的存档改名，按定义不算早停
complete          epochs_actual >= epochs_nominal
early_stop_legit  epochs_actual <  nominal 且 epochs_actual >= best_epoch + 99
interrupted       其余（epochs_actual < best_epoch + 99）
```
理由：`patience` 未显式传 ⇒ ultralytics 默认 **100**，故合法 patience 早停必须
`act ≈ best_ep + 100`；且名义轮数 ≤100 的 run **不可能**触发 patience ⇒ 其不满轮一律 `interrupted`。

**实测分布**：

| outcome | A | B | 合计 |
|---|---|---|---|
| `complete` | 747 | 1047 | **1794** |
| `early_stop_legit` | 9 | 28 | **37** |
| `interrupted` | 30 | 10 | **40** |
| `archive_snapshot` | 18 | 32 | **50** |
| 合计 | 804 | 1117 | **1921** |

## 六、★ 种子机制（2026-09-30 实测更正，**影响 A5 与全文"seeds"一词**）

**结论：run 名里的 `s<N>n` 与 `args.yaml` 里的 `seed` 不是同一个量。**

```yaml
# A_runs_20260929/runs/a0_100_10p_100ep_base_s43n/args.yaml
name: a0_100_10p_100ep_base_s43n
seed: 42                 ← 名字写 s43，args.yaml 却是 42
deterministic: true
```

全库直扫 `args.yaml`（不经底座）：

| 机器 | `seed: 42` | `seed: 0` | 其它 |
|---|---|---|---|
| A（901 个 args.yaml） | 856 | 94 | 1（529） |
| B（1820 个 args.yaml） | 1109 | 687 | 24（43/44/45） |

而训练日志里写着：

```
[shuffle-seed 45] permuted 1150 train im_files
```

driver `train_obj.py` 的 `--shuffle-seed` 帮助文字即
"**train im_files 确定性置换种子（seed 机制修复；None=不置换）**"。

**⇒ 口径裁定**：

* **本次战役的"种子" = 训练文件列表的确定性置换种子**（名字里的 `s<N>n`）⇒ 底座列 **`seed_name`**；
* `args.yaml` 的 `seed`（torch/ultralytics 侧）**几乎恒为 42**（部分为默认 0）⇒ 底座列 **`seed_args`**，
  **不是**实验变量，**禁止**用它做配对；
* 例外需注意：B 侧有 **24 个 run** 的 `seed_args ∈ {43,44,45}`（真种子也变了），
  这些格与其余格**方差来源不同**，做 A5 时必须单列或剔除。

**对论文的直接影响**：所谓"十配对种子"实为**十种数据顺序**，初始化与数据增强的随机性**未被采样**。
这既是**必须明写的方法学事实**（方差预算只花在了一个来源上，
正是 [Bouthillier] 所说的"deliberately spend variation budget"的极端形态），
也**限制**了结论的适用范围（不能声称覆盖初始化方差）。⇒ A5 必须按这个真相重做。

## 七、★ `family` 列与**族混杂**（2026-09-30 口径修正，**影响所有按格汇总的分析**）

**`family` = run 名第一段 = 批次**（`b2` / `t1c` / `mech` / `r10` / `s2df` / `g3clean` / `y11` …）。

**问题**：同一个 `(配对, 数据集, epochs)` 下**常常混着多个族**，而它们**不是同一次实验**。
旧的分析格键（`06_A25.py` 的 `(pair, epochs)`、`04_A1_grid.py` 的 `(pair, budget, epochs, loss)`）
**都不含 `family`** ⇒ 把不同批次平均掉，甚至**改掉结论方向**。

实测影响（详见 `analysis\A7_族混杂复核.md`）：

| 量 | 修正前 | 修正后 |
|---|---|---|
| 旧格键可分析格 | 60 | — |
| 其中**混了多族** | **9**（15%），其中 1 格各族**符号相反** | 0 |
| A1 可配对核心格 | 126 | **145** |
| `claims` 的 ❌未复现 | **8** | **0** |

**纪律**：**论文每个招牌数字都应点名一个族**。已点名的对应关系：

## 八、★ `run → backbone` 映射（2026-09-30 补齐，**A1 唯一的架构缺口已闭合**）

底座原来的 `model` 列只记**预训练权重**、不记 backbone ⇒ 架构轴只能从 run 名 token 推断（只能给下界）。

另 31 条链未走通（`unknown(epoch80) 20`、`unknown(shapeiou_fusion_best) 6`、`unknown(best) 5`）。

★ **招牌族的 backbone 已逐一核过**（`analysis\A1b_架构链映射.md`）：

## 十、★ 本底座新增的**口径纪律**（逐条都有实测依据）

1. **格键必须含 `family`**（§七）；跨族合并**不能一律禁用**，但必须**显式声明**。
2. **报数必须写明"哪一侧 / 哪一列"**。本底座有 6 个可选列：
   `test_map50_95` / `test_map50` / `best_map50_95` / `best_map50` / `last_map50_95` / `last_map50`。
   ★★ **论文的用列是"分组"的，必须整节声明**（2026-09-30 两次独立发现）：
   * **干预小节 §4.1 / §4.2 / §5 → `test_map50_95`（test 侧）**；
   * **对照小节 §4.3 / §4.4 → `best_map50_95`（val 侧最优轮）**。
   实例：`mask→mende`（族 `t2` · `mende_20p` · 100ep · n=5）test 侧 **−0.9020（4/5）**、
   val-best 侧 **−1.4878（t=−4.023, 5/5）** ⇒ **论文 §4.3 的 −1.49 是后者**；
   `y11_shwd→sfchd` 亦然。**同一格换列会给出完全不同的数** ⇒ 在 §3 用一句话写清即可，
   否则第三方无法复算。
3. **同一 `(种子, 臂)` 可能有多行**（完成的 run + 它的 `.incomplete_` 存档快照，后者常无读数）
   ⇒ 取值时**先扔掉该列无读数的**，再按结局优先级（`complete` 最优）取，**不得**简单"取最后一行"。
4. **`sio_b_results.csv` 是追加写**：多读数时本底座取**首次**（与论文 §4.1 逐位吻合），
   31 条 run 带 `dup_test_line=1`。论文报这些格必须写明"取哪一次"。
5. **"种子"的写法**：*ten paired data-order permutations (torch seed fixed at 42)*，**不得写 "seeds"**。
6. **计时模型：有效但系统性低估**（`analysis\A4c_计时模型_用真实图数复核.md`，**取代同日的 A4b**）。
   登记的 `s/ep ≈ 2.727e-3·val + 4.85e-3·train` 跨 **40 个数据集 R² = 0.948**；
   `sfchd_20p_b`（本文 §4.2 的招牌格）**精确命中**；但中位比值 **0.79×** ⇒ 整体低估 ~21%，
   原因是 **val 系数偏小**（重拟合 3.89e-3 = 登记的 1.43×；train 系数几乎不变 0.98×）。
   残差集中在 `dota15_*`（0.22–0.38×）⇒ **分辨率效应**，不是模型形式错。
   图数取自 **`base\dataset_split_counts.csv`**（从机器上的 `train:`/`val:` 目录计数，**不需日志**）。
   ⚠ `A4b` 的"不可识别、不要报计时模型"**已作废** —— 它错在"图数只能从日志取"这个前提。
7. ★★ **`family` 是"批次"标签，不是"架构"标签**（2026-09-30 二次更正）。
   `family` = run 名第一段 ⇒ `b2_y11_sf_base100_s45n` 的 family 是 **`b2`**，而它**正是 §4.4 的架构对照 run**。
   于是：
   * **按 `family='y11'` 圈定架构 ⇒ 漏 7 个种子**，把 §4.4 的 100ep 从 **n=10 缩到 n=3**
     （论文的 `−0.0050, t=−0.099` 就是这 3 个种子；**全 10 个给 `+0.193, t=+2.04`**）；
   * 反过来 `b2` 族里**混着 yolo12n 与 yolo11n 两种架构**。
   ⇒ **架构轴必须用 `base\run_backbone_map.csv` 的 `backbone` 列**，不能用 `family`。
   实现见 `scripts\_cells.py` 的 `arch_cell()`；登记见 `A7_族混杂复核.md` §7。
8. ★★ **结局可用性（`ok_outcome()`，2026-10-01 新增）—— 与"该列是否非空"是两件事**。
   旧 `_pick` 只要求"该列非空"，但**列是带偏向的**：
   * `test_map50_95` 由 driver 跑完 eval 后才写进 `sio_b_results.csv`
     ⇒ 中断件**没有**这一列 ⇒ 旧逻辑在 test 侧**恰好安全**；
   * `best_map50_95` 来自 run 自己的 `results.csv`（val 侧最优轮）
     ⇒ 中断件**照样有**这一列 ⇒ 旧逻辑在 val 侧**会被污染**。
   实测同一格（`mask→mende` · 族 `t2` · `mende_20p` · 100ep）：

14. ★★ **`pair_of` 把 `model` 写进格键 ⇒ "格内混架构"的普查**永远**报 0**（2026-10-02 发现的循环论证）。

    * **实测**：补实验给出同数据/同族/同轮数、**只换 backbone** 的 2×2×10；
