### 3.3 ⚠ 第三格 `visdrone→dota15` · `r10` · 100ep · `dota15_20p_3way.yaml`

**这一格不干净，必须点名**（补材说它"没有 clean-protocol 对应物"，底座显示的是另一种情况）：

* 该格在底座里**确实有 3way run**，且 `n=10`、增益 `+3.652`（t = +37.57）；
* 但每个 (seed, 臂) 下**同时躺着多份**：

| 后缀 | 含义 | 影响 |
|---|---|---|
| 无后缀 | 正式件 | — |
| `_oomfix` | CUDA OOM 后 CPU 回退重跑（§6 的审计对象） | 多读数 |
| `_REPB` | 重跑批 | 多读数 |
| `_PARTIAL_0011` | 存档快照 | `interrupted` ⇒ `ok_outcome()` 判不可用 |

* `_pick` 会取"结局最好 + 名字最短"的那一份 ⇒ 本格取到的是**正式件**，读数确定；
* 但这意味着该格的 `+3.652` **不能**当作"干净三方协议读数"引用 —— 它所在的分支混着重跑件。
  ⇒ **正文只引前两格**；第三格登记为**有 3way run 但不作为 clean-protocol 证据**。
* ⚠ 同格存在 `_oomfix` / `_REPB` / `_PARTIAL_<数字>` 后缀件还会触发另一件事：
  这些后缀让 `norm()` 的 `_s(\d+)(n?)$` 匹配失败 ⇒ `seed_used` 回落 42。
  **当前 0 次被 `_pick` 选中**，但已加断言 `S-1`/`S-2` 常驻钉住（见 `14_verify_claims.py`）。
