## 二、★ 未被捕获的部分（**必须与上表同读**）

1. **没有在运行时抓 `pip freeze`**：`numpy` / `scipy` / `pyyaml` / `opencv-python` 等**传递依赖的精确版本
   没有留痕**（放行件的 `requirements.txt` 只列了四个顶层包且未钉小版本）。
2. **没有记录驱动版本与 cuDNN 版本**；`+cu121` 只确定 CUDA runtime 的主版本。
3. 因此：**同一份代码在不同传递依赖下重跑，可能产生与本文不同的绝对读数**。本文对这一点的立场与
   §6(b)、U.1、U.2 一致 —— **水平量会被实现与版本移动，配对增益不会**；U.1/U.2 已用**官方
   `pycocotools`** 独立复评给出量级（水平动 0.51 pp、配对增益动 0.25 pp）。
4. **可补做的**（需重开 A/B 机并重跑一次，约 5 分钟）：`pip freeze > provenance/env_pip_freeze.txt`。
   本件立此存照，标明**该缺口是已知的、有界的**，而不是遗漏。

## 三、复现者应如何用这一件

- 要**复算本文的数字**：用 `ultralytics==8.4.120` + `torch==2.4.0`（CPU/GPU 均可）读放行的逐 run 表，
  不需要重训 —— 因为 §4 的所有量都从 `base/run_table_canonical.csv` 复算；
- 要**重训**：按上表主版本即可；若绝对读数与本文有小差，先查传递依赖版本，再看 U.1/U.2 的实现敏感性量级；
- **不要把本文的绝对 mAP 当作跨版本常数**：配对对比才是本文的结论载体。
