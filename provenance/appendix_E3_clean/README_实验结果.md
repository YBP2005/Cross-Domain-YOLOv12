### 2.7 口径约定（E3 与 E1 通用）
- `results.csv` **只有 val 列**（`metrics/mAP50-95(B)`，第 9 列）。`args.yaml` 为 `val: true`、`save_period: 5`。
- `train_obj.py` 训练结束后加载 **`best.pt`（按 val 选出的最优 checkpoint）**，跑一次 `mm.val(split='test')`，把 `name,loss,epochs,map50,map95,mp,mr` **追加**到 `/workspace/sio_b_results.csv`（A、B 两机各自一个同名但不同的文件）。第 5 个字段 = test mAP50-95。
- 因此 **test 读数的准确含义是「按 val 选出的最优 checkpoint，在 test 上评测」**。
- 本件 E3 的论文端点一律用 **test 列**；best-val 列作为副口径同时报告并标明不可比。
- 要求：**按 run 名精确过滤**、同 run 多行取**最后一次**。本次 E3 的 20 条 test 行**每个 run 名只出现 1 次**（无重复追加）。

## 3. E1：匹配语料单元（d15tod15）上的 lr 档位扫描

### 3.1 设计与基线来源
- 36 → **33** 个 run（见 §1.3）：3 档预算 × 4 个 lr 档 × 3 种子（s42/43/44），去掉 `lr5x@50p` 的 3 个。
- 档位（相对 base 0.001 的倍数）：`2.5×` = 0.0025、`5×` = 0.005、`10×` = 0.01、`20×` = 0.02。
- 预算：`10p`/`30p`/`50p` → `dota15_10p.yaml` / `dota15_30p.yaml` / `dota15_50p.yaml`。
- 配方（A 机，与既有 g1_c1 逐字一致）：`--pretrain /workspace/weights/dota15_pretrain.pt`、100 epoch、SGD、momentum 0.925、weight_decay 1e-4、cos_lr false、batch 32、imgsz 640、`--shuffle-seed`。
- **1×（base）臂不在 E1 清单内**，取自既有 g1 族（B 机，10 seeds，args 与 E1 逐字一致，仅 lr0 不同）：

| 预算 | 1× base 臂 | 既有 5× 策略臂 |
|---|---|---|
| 10p | `g1_c1_d15tod15_base100_10p_s42..s51` | `g1_c1_d15tod15_strat100_10p_s42..s51` |
| 30p | `g1_c5_d15tod15_base100_30p_s42..s51` | `g1_c5_d15tod15_strat100_30p_s42..s51` |
| 50p | `g1_c2_d15tod15_base100_50p_s42..s51` | `g1_c2_d15tod15_strat100_50p_s42..s51` |

- ★ **`50p` 的 5× 格来源**：E1 的 `lr5x@50p` 未跑（dedup 去掉），本表该格取自 **`g1_c2_d15tod15_strat100_50p_s42/43/44`（B 机）**。
- ★ **交叉验证（跨机可复现性）**：E1 的 `lr5x@10p`、`lr5x@30p` 与既有 `g1_c1/g1_c5 strat` 在同种子、同列上**逐位相同，`max|diff| = 0.00e+00`**：

> ⚠ 注意两列在 10p 的**可分辨性相反**：best-val 下 5×→2.5× 的 0.3730 pp 超过 MDE(0.2463)，test 下 0.3800 pp 未超过 MDE(0.4189)。结论必须两列同时给，不能只挑一列。

### 3.5 回答 E1 的问题

**（a）最优倍率是否随预算移动？**
**是（best-val 与 test 两列一致）**：10p 的 argmax 是 **2.5×**，30p 与 50p 的 argmax 是 **10×**。即最优点从 2.5× 上移到 10×，30p/50p 位置相同。

**（b）这个移动是否"可分辨"？不能只报 argmax。**
- **10p**：argmax = 2.5×。5× 比它低 **0.3730 pp**（best-val，MDE 0.2463 ⇒ **可分辨**；test 0.3800 pp，MDE 0.4189 ⇒ 不可分辨）。
- **30p**：argmax = 10×，但只比 5× 高 **0.1487 pp**（MDE 1.0513）⇒ **分辨不出**。30p 上 5×、10× 属同一水平。
- **50p**：argmax = 10×，只比 5× 高 **0.1160 pp**（MDE 0.2179）⇒ **分辨不出**。
⇒ 严格表述：**最优点确实移动了（2.5× → 10×），但"5× 不是最优"这件事只有在 10% 预算上可分辨，且方向是"应该用更小的倍率"。在 30%/50% 上 5× 与最优档在噪声内无法区分。**

**（c）在 argmax 档位下，各预算的增益是多少、符号是否仍然成立？**
| 预算 | argmax 档 | 该档增益（best-val） | 该档增益（test） | 符号 | §5 说法 |
|---|---|---:|---:|---|---|
| 10p | 2.5× | **−0.2410** | **−0.2333** | **负** | "10% 为负" ✅ 成立 |
| 30p | 10× | **+0.9270** | **+0.9400** | **正** | "30% 为正" ✅ 成立 |
| 50p | 10× | **+1.9813** | **+1.9633** | **正** | "50% 为正" ✅ 成立 |

**符号结构对"按预算重新选最优倍率"是稳健的**：10p 上**四个档位全部为负**（−0.24 / −0.61 / −1.46 / −2.77），换任何倍率都救不回正号；30p/50p 上所有档位为正。

**（d）固定 5× 的代价有多大？**
- 10p：固定 5× 相对最优（2.5×）**高估伤害 0.3730 pp**（best-val；test 0.3800 pp）。方向为"对策略臂不利"，即稿内 10% 的负结论**不是**由选 5× 造出来的，但**幅度被放大了约 0.37 pp**。
- 30p：固定 5× 相对最优（10×）**低估收益 0.1487 pp**（不可分辨）。
- 50p：固定 5× 相对最优（10×）**低估收益 0.1160 pp**（不可分辨）。
⇒ **§5 的固定 5× 比较在符号层面是安全的；需要写明的只有一条**：低预算端的伤害幅度含约 0.37 pp 的倍率选择成分，且在 30%/50% 上 5× 与各自最优档在 3 种子的分辨力下不可区分（10 种子参考显示 5× 的增益本身仍远超 MDE）。

**（e）需要在稿内加的限制（建议措辞）**：E1 每格只有 3 个种子（γ(3) = 3.0965 门槛很高），因此"5× 非最优"仅在 10% 预算上达到可分辨；30%/50% 上把 5× 换成 10× 的收益（0.15 / 0.12 pp）低于该格 MDE，**不能**声称 5× 在那些预算上被证明次优。同时 10% 上"更小的倍率更好"这一点是可分辨的。
