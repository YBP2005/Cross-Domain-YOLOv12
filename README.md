## 二·补·零 ★★ **运行顺序：先跑守卫，再跑普查**（不遵守会得到假的报红）

`code/` 下有两类脚本，**它们对同一批文件的关系不同**：

| 类 | 例 | 写什么 |
|---|---|---|
| **守卫/核验类**（只读或只写自己的报告） | `14_verify_claims.py`、`16_draft_tag_paths.py`、`44`、`45` | 只读 `base/` 与 `M3_draft/`，把核验报告写进 `deliver/` |
| **普查/生成类** | `26_A9_*`、`29_A12_*`、`30_A13_*`、`31_A14_*`、`32_A15_*`、`33`、`34`、`35` | **重写 `analysis/` 与 `deliver/` 里已冻结的生成件** |

⇒ **`analysis/` 与 `deliver/` 是"已冻结的生成件"，不是输入。** 如果你先跑普查类、
再跑守卫类，守卫就会对着**刚被重新生成过的一批数**做核验 —— 那时报出的"漂移"
**不是稿子的缺陷，而是你先换了地板**（我实测：先跑普查后，`16` 报 `A1 可配对核心格` 由冻结值漂成 **81**）。

**所以**：

1. **要核验稿内数字 → 先跑守卫类**（上面的"怎么跑"五条就是这一类）；
2. **要重造生成件 → 那是一次有意为之的再生成**，之后必须**重跑守卫类**并接受它们可能报红；
3. **不要把两类混在一个循环里跑**。`build/verify_repo_isolation.py` 是唯一例外 ——
   它在**临时隔离副本**里逐个跑，因此不会污染你手上这份。

**另一条已隔离的件**：`code/archive_only/01_build_base.py` **会从 `raw/` 重建底座**，
而放行副本**不带完整原始归档** ⇒ 跑它会把 `base/` 覆盖成不完整的版本（实测 1,117 run vs 正确 2,336），
**并连带让 `14/16/40/41/43` 集体失败**。它已带**覆盖守卫**：不给 `--allow-overwrite` 一律拒绝执行。

## 四、复现的前提与限制

### 4.0 依赖与运行环境（★ 先读这一段再跑脚本）

本目录的脚本**不是开箱即跑**。最小依赖：

```
python >= 3.10
pip install numpy scipy
```

* **`scipy`**：**六个脚本**（`code/07`、`14`、`43`、`45`、`46`、`g1_readout`）在干净环境下**会直接报错退出**：
  `code/43_A24_power_audit.py` 与 `code/45_verify_appendix_P_arithmetic.py`
  报 `ModuleNotFoundError: No module named 'scipy'`。
  安装 `scipy` 后六者均可跑（且都带 `--self-test` 阴性对照）。
* 其余脚本只需标准库与 `numpy`；`_cells.py` 也只用标准库。
* **不需要** `torch`/`ultralytics`：本包不跑训练也不跑推理（见下一段“没有 checkpoint 随包放行”）。

★ 如果你只想核**主稿某一个数字**，一般只需
`code/_cells.py` + 一行读表代码，**不需要 scipy**。


* **数据是"每 run 一行"的汇总**，不是权重。**没有 checkpoint 随包放行**，因此
  "重跑训练 → 逐位复现某读数"**不在本包能力范围内**；本包支持的是
  **"从已发布的 per-run 表复算每个报告的数字"**，这正是主稿 §4/§5 的 `✅CONFIRMED` 标签所声明的两级之一
  （另一级是 §6 的归档审计件）。
* **训练协议快照**（`data/args_protocol_snapshot.csv`）取自**租用机器的活体现场**，机器已关；
  快照本身即交付物。`code/39_verify_protocol_fingerprint.py` 对它做**逐 run 断言**（含 `--self-test` 阴性对照）。
* 底座含 **32 行外来项目的 run**（另一课题）与 **969 行默认名产物**，`39` 会逐类报出并断言
  "**底座里的本课题 run 不得落入任何例外类**"。全量 2,362 行中，**2,336 行**是本课题 run。
