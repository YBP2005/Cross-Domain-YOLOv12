# G1 接线错事故报告（2026-10-04）—— 由监视子代理报出并复核确认

## 0. 一句话

**队列把"格"与"预算"相乘了，而预算只是标签、不选数据** ⇒ **每个格被跑两遍、总量 80 翻到 160**。
**由监视子代理在巡检 batch/OOM 证据时发现**，我复核后**立即止损**，已修根因并重启。
**损失：B 机 3 个 run（其中 1 个跑满 100 轮）+ A 机 2 个残件**，其余全部保住。

## 1. 缺陷本身

`g1_queue.py` 里三处配合出错：

```python
CELLS = {'c1': dict(data='.../dota15_10p.yaml'), 'c2': dict(data='.../dota15_50p.yaml'), ...}
queue = [(c, arm, b, s) for c in cells for b in budgets for arm in arms for s in seeds]
                                         ^^^^^^^^^^^^^^^^^^ 与 cell 相乘
# run_name 用 b（预算）拼名字，但**数据路径只由 CELLS[c]['data'] 决定**
```

⇒ **`--budgets 10p 50p` 对每个格都跑一遍，两遍用的是同一份数据、只换名字**。

**实测证据（子代理提供，我复核）**：

| 证据 | 值 |
|---|---|
| `g1_c1_..._base100_50p_s42/args.yaml` 的 `data:` | `dota15_10p.yaml`（**10p 数据**） |
| `g1_c1_..._base100_10p_s42/args.yaml` 的 `data:` | `dota15_10p.yaml`（同上） |
| 两者 `results.csv` 的 100 行 mAP50-95 | **逐行完全相同** ⇒ 确认是重复 |
| 两者耗时（`_g1_timing.csv`） | 1210.7 s vs 1214.6 s ⇒ 同一档数据 |

（★ 我第一版用**整文件 md5** 判重复，判成"不同"——因为 `results.csv` 含时间/显存等 wall-clock 列。
改用**数据列投影**后立刻判出重复。**这是一个判据设计错误，已记入脚本注释。**）

## 2. 正确的接线（与《G1实验方案》§1 的 4 个格一致）

**格本身就编码了预算**，每格**只对应一个** (域对, 预算)：

| 格 | 域对 | 预算 |
|---|---|---|
| c1 | `dota15→dota15` | **10p** |
| c2 | `dota15→dota15` | **50p** |
| c3 | `dota15→aitod` | **10p** |
| c4 | `dota15→aitod` | **50p** |

⇒ 总计划 = 4 格 × 2 臂 × 10 种子 = **80 run**（每机 40），**不是 160**。

**修法**：
1. `CELLS` 每格**自带 `budget` 字段**；
2. `run_name(cell, arm, seed)` —— **预算取自格自己**，不再由调用方传；
3. **删除 `--budgets` 参数**（免得以后又有人乘一遍）；
4. 队列构造改为 `[(c, arm, CELLS[c]['budget'], s) for c in cells for arm in arms for s in seeds]`；
5. **加不变式**：**同一域对内**每个预算恰好绑一个格，否则拒绝启动（exit 4）。

★ 不变式**第一版写错**：我写成"全局预算唯一" ⇒ 立刻报 *"预算 10p 同时绑到 c1 与 c3"* ——
那是**假红**（c1 与 c3 分属两个域对，**本来就该共用 10p 标签**）。已改成**按域对核**。

### 4.1 ★ 705 / 706 已查清（**"缺标签"假设被推翻**）

由监视子代理查证并复核：

| 项 | 实测 |
|---|---|
| `train/50_percent/images` | **706** 张 |
| `train/50_percent/labels` | **706** 个 `.txt` |
| 图无对应标签 / 标签无对应图 | **0 / 0** |
| `labels.cache` | 含全部 **706** 个名字 |
| **`im_files` 实际数** | **705** |

**真因**：`P0334.jpg` 的 `P0334.txt` 坐标**非归一化/越界**（`[1.056542 1.058319]`，>1.0）
⇒ ultralytics 打印 `ignoring corrupt image/label` 并**丢弃该 pair** ⇒ 705。
另：`P1531.txt` 是**空标签**，**保留为背景图**（故是 705，不是 704）。

⇒ **是既有的标签脏数据，不是缺文件**；cache mtime（Sep 27 / Oct 1）显示**早于接线错**。
**对 G1 推断无影响**：同一预算档内两臂共用同一 705 张。
**10p 不受影响**：141 图 / 141 标签 / `permuted 141`。

★ **AI-TOD 侧无同类隐患**（子代理纠正了它自己上一轮的路径错误后重扫）：
`labels/train_aitod_10p` **1121/1121**、`train_aitod_50p` **5607/5607**、`val` **2804/2804**，
配对缺失 **0**，内容扫描 **0 空 / 0 越界** ⇒ A 机到 c4 时**不会有同类丢弃**。

### 4.2 速度模型（子代理反解，可用于 ETA）

| 档 | 实测 s/轮 | 图像数 |
|---|---:|---:|
| 10p | **11.5** | 141 |
| 50p | **14.7** | 706 |

差**仅 1.28 倍**（不是 5 倍）⇒ 每轮成本被**固定的 val 通过**主导。
解 `141k + V = 11.5`、`706k + V = 14.7` ⇒ **V ≈ 10.7 s**（458 张 val）、**k ≈ 0.0057 s/图**。
反代核对：141×0.0057+10.7 = **11.5** ✓、706×0.0057+10.7 = **14.7** ✓。
⇒ **B 机 50p 单 run ≈ 24.5 min**（不是我先前外推的 95–100 min——那个外推把 val 成本忽略了）。

★ 这也解释了为什么**旧重复与 10p 的耗时几乎无法分辨**（1210.7 vs 1214.6 s）；
**修复生效的证据恰恰是这 1.28 倍的差**——它是"两档真的读了不同数据"的**可观测量**。

## 5. 教训

1. **"参数只进名字、不进数据"是最难发现的一类错**：名字看起来完全正确，`args.yaml` 也自洽，
   只有把**两个应当重复的 run 逐行对比**才会暴露。
2. **判重复不能用整文件 md5**（含 wall-clock 列）⇒ 必须用**确定性数据列的投影**。
3. **守卫要核"计划总数"**：如果一开始就有"计划应等于 4 格 × 2 臂 × 10 种子 = 80"这条断言，
   队列一构造就会报 160 ≠ 80。**现在这条不变式已加进脚本。**
4. **子代理的价值在这里被证明**：我的巡机只看"进程活着 / 轮数在涨 / 无 OOM"，
   而它去核了 **batch/OOM 证据与 `args.yaml` 的一致性**，才撞见这个错。
