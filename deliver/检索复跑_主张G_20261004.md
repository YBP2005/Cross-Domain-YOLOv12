# 检索复跑记录 · 主张G（隔离式骨干替换 / isolated backbone swap）· 2026-10-04

**被检主张（G）**：固定微调语料、20% 标签预算、100 epoch、十条数据序置换，唯一变量是**已发布骨干**（`yolo11n` vs `yolo12n`）；学习率增益在两骨干、两种列口径下均存在（test 列 +3.75 / +3.51 pp；val-best 列 +7.57 / +8.66 pp），四个 arm×backbone 单元内 10/10 种子为正；两骨干间增益差不显著（test 列 −0.24 pp, t=−1.59, p=0.15；val-best 列 +1.10 pp, t=+2.08, p=0.07）。论文自陈：已发布 checkpoint = 架构 + 其自带 COCO 权重，故只隔离"按发布状态"的骨干，而非架构本身。

**要检的对照面**：迁移/微调研究中的架构·骨干比较；固定流水线只换骨干的工作；骨干选择与超参（尤其学习率）在检测中的交互。

## 4. 最接近的一篇 + 判词

**最接近的一篇：K1 — Ning Ding, Azim Eskandarian, "The Impact of Different Backbone Architecture on Autonomous Vehicle Dataset", arXiv:2309.08564 (2023)。**

它在**同一层**：在目标检测任务内，把骨干架构当作唯一自变量，在 KITTI / NuScenes / BDD 三个驾驶数据集上比较不同骨干的检测表现——即"固定检测流水线、只换骨干"。它的摘要原话是 "to compare the performance of different backbone architectures on object detection tasks"。**最接近的协议层对手是 K2（Mahadevkar 等 2024, PeerJ CS）**：同语料、80/20 划分、**相同 epoch 数**、只换 6 个骨干，随后再对前三名骨干做超参调优——这是本次检索中唯一同时命中"固定预算的隔离式骨干比较"与"骨干 × 超参关系"两点的先例。**判词（是否威胁主张）**：`isolated backbone swap` 这一**机制**并不新颖，检索到的先例已把它作为标准做法反复使用（K1、K2、K3、K14、K15）；主张的自陈注意事项（已发布 checkpoint 混淆"架构"与"其自带权重"）在文献中也已被触及（K7 把架构与预训练权重分开考察）。因此审稿人完全可以说"固定流水线只换骨干、以及已发布权重带来的混淆，都是已做过的事"。但**没有**找到任何工作：在两骨干下同时给出**学习率预算增益**、用**十条数据序置换配对**、并对**增益之差**做显著性检验（主张的 −0.24 pp / t=−1.59 / p=0.15 与 +1.10 pp / t=+2.08 / p=0.07）。K4 最接近"yolo11n 对 yolo12n"这一具体对象，但它是已发布套件横评、未统一预算与超参、无种子配对与增益差检验。**结论：主张的"机制外壳"不新颖，可被 K1/K2 显著压低新颖度；主张的"学习率增益在骨干间的差异不显著"这一点在本次通道与措辞下未找到先例**——这也正是主张需要自我定位的地方：它不应主张"首次做隔离式骨干对照"，而应主张"首次对学习率预算增益做跨骨干的配对显著性检验"。

## 5. 证据强度声明

- **可达通道数**：`probe` 的 7 个探测目标（crossref、datacite、arxiv-abs、arxiv-api、openalex + 两个阴性对照）**全部返回 200**，两次探针结果一致；实查阶段额外使用的 arXiv HTML 检索页与 OpenAlex 单作品端点亦为 200；唯一完全不可达的是 `peerj.com`——经 `doi.org` 返回 **403 + Cloudflare JS 挑战**，故该出版方正文未被取到。
- **是否退化**：有，且已区分记录。(a) **arXiv API 在并发下被限流**：7 次 429/1 字节；父代理在同机复核为 200，故判定为并发限流而非通道损坏；7 次全部记为抓取失败，未写入任何"零命中"结论；`sleep 5–6` + 单次 25 s 重试后恢复 200。(b) **OpenAlex `search=` 判别力退化**：返回大量无关条目（如 AlphaFold、蛋白结构），故改以 `filter=title_and_abstract.search:` + `select` 为主，`search=` 结果仅作覆盖、未单独采信。(c) **arXiv HTML 检索页受脚本 20000 字节打印上限限制**，单次只可见 1–2 条，仅作补充。
- **符号学约定**：arXiv 零命中的字节签名是 **~700–800 字节**（阴性对照 728 字节）；有命中为数千至数万字节（正向对照 `YOLO object detection` 20762 字节）。1 字节 + 429 = 限流，**不是**零命中。本报告对三者严格区分。
- **结论的措辞边界**：本报告的结论是"**在这些通道与这些措辞下未找到**"直接先例（尤其是"两骨干下学习率预算增益之差"的配对显著性证据），**不是**"此类工作不存在"。理由：peerj.com 正文不可达；arXiv API 曾限流；两条候选（K11、K12）仅有题名、摘要不可得，未能核验；维普/CNKI、Scopus、IEEE Xplore 全文、Google/Bing/Semantic Scholar 均未使用（按任务约束）。
- **引用纪律**：本报告所有引号内文字均取自本次实际抓取到的文本（arXiv 落地页正文或 OpenAlex 摘要端点返回的 inverted-index 重建文本）；无一条来自记忆或推测。
