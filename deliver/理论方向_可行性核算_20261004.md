## 一、★ 值得做：**30 轮增益预测它自己的衰减**（$r=-0.834$）

**做法**（只读底座，用项目自己的格解析器 `scripts/_cells.py`）：取同时有 **30ep 与 100ep**
配对增益的 `(pair, family, lb)` 格 —— 共 **39 格** —— 然后看"30ep 的增益水平"与
"100−30 的衰减量"的关系。

| 量 | 值 |
|---|---|
| 30ep 增益均值 | **+1.745 pp**（39 格中 **6 格为负**） |
| 100ep 增益均值 | **+0.685 pp**（39 格中 **14 格为负**） |
| 逐格衰减（100−30） | 均值 **−1.060 pp**，中位 **−0.381**，**27/39 为负** |
| **Pearson** corr(增益@30, 衰减) | **r = −0.834，p < 0.001** |
| Spearman | ρ = −0.521，p = 0.001 |

**读法**：30ep 增益大的格，随后的衰减也大。这是把 §4.2 那个单格曲线（$+3.656\to+1.495$）
变成**跨 39 格的规律**。**两个数字本身互相独立**（增益@30 与 100−30 的差没有共同项），
所以这不是同侧相减造成的假相关。

**★ 但有一个必须自己先说的漏洞**：这正是**均值回归**的典型形状（初始水平高的，后续变化更负）。
所以本结果**只能**读作"**衰减幅度与初始增益成比例**"，**不能**直接读成"头寸（headroom）解释"。
⇒ 若要当成**机制**用，必须补一步控制：把 **base 臂在 30ep 的绝对准确率**（或它的位置）
一起放进回归，看**头寸代理在控制了初始增益之后是否仍有增量解释力**。这一步还没做。

**它为什么值得做**：本稿现在**没有任何一处**把 §4.2 的单格曲线推广到全档案；
而这个结果（39 格、r = −0.834）正是"**曲线是规律，不是个例**"所缺的那一句，
且**不需要新数据**。若控制回归后仍显著，它可以升格为"§4.2 的曲线在全档案上成立"的**定量**支撑。

## 二、✗ 不能做（已自己否掉）：把"所需种子数"当成事前设计规则

我按稿内 §9 的公式反解"要多少配对种子才能分辨该格的 $\Delta$"：

| 量 | 值 |
|---|---|
| 能反解出有限所需 $n$（≤200）的格 | **142 / 147** |
| 所需 $n$ 的分布（按观测 $n$ 分档） | $n{=}3$ 档 **71** 格、$n{=}5$ 档 13、$n{=}10$ 档 53、$n{=}13$ 档 3 |
| 若把每格都提到 $n=10$，可分辨格数 | **121 / 147** |
| 按 $n=3$ 算，可分辨格数 | 77 / 147 |

**为什么不能用**：`所需 n` 用的是**观测到的 $\Delta$ 与 $\hat\sigma$**，而这两样**只有在跑完之后才知道**
⇒ 它是**事后**量，**不能**当成"事前该跑几个种子"的规则，否则就是**选择性推断**
（观测 $\Delta$ 大的格当然"只需 3 个种子"）。**这条恰好是审稿人会抓的**，所以我在合成就把它标成"不要写"。

**真正可做的是另一件事**：用**先验量级**（同一 family 内 $\Delta$ 与 $\hat\sigma$ 的分布）做
**前瞻功效表**，并明写"$\Delta$ 未知、只能按量级假设"。这需要按 family 分组统计，尚未做。
