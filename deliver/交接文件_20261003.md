## §7 ★ 坑与教训（**务必读，这些坑本会话都踩过**）

### 7.1 代码/工具类

1. **绝对不要用 `_d` 作局部变量名**（`16_draft_tag_paths.py` 里 `_d` 是全局正文文本，**踩过两次** ⇒ 无关守卫集体报红）。用 `_diff`/`_dens`。
2. **`%` 出现在 `_must` 的 label 里会炸**（`ValueError: unsupported format character`）⇒ 写成 `80%%`。**写 markdown 时同样**：正文含 `%` 就别用 `%` 格式化，用占位符替换（本会话踩过）。
3. **`\n` 在 heredoc 写的 python 源码里会变成真换行**（反复踩）⇒ 用 `.*?`/`\s*` 或 edit 工具。
4. **守卫里的"期望字符串"必须与稿内**逐字**一致**（精度、加粗、顺序都要对）。
5. **任何随编辑变化的量都要"算出来"，不能写字面常量**——"空守卫比没有守卫更危险"。
6. **解析失败必须报红**（`_must(..., target=_XCHK)`），不能静默跳过。
7. **`_must` 默认写 `_RCHK`（报告）**；要写稿内值必须传 `target=`。
8. **`curl -w "#HTTP=%{http_code}"` 放进 `%` 格式化的 python 串里会炸** ⇒ 用字符串拼接。
9. `_pack_runs.sh` 的循环列表只展开一次；`flock` 拒绝行是**正常行为**。
10. **bash 里没有 `pwsh`**（有 `powershell.exe`）；`regex` 匹配大小写要留意（我用大写 `YOLO` 漏掉了小写 `yolo11n`）。

### 7.2 判断类（**比代码坑更值钱**）

11. ★ **判"某文献是否存在/在不在某卷"必须解析标识符本身**（arXiv 落地页 / `doi.org` 落地码），
    **绝不能用"抓目录页 grep 关键词返回 0"来推断**。本会话我据此**误判 `[Springer] PMLR v267` 无效**，
    实际它**是对的**（第一作者姓氏就是 Springer，arXiv:2503.19206，ICML 2025 确实收录）。
12. **`[LeakageBench]` 的 DOI 由 DataCite 注册**（Zenodo）⇒ **Crossref 会回 "Resource not found"，
    这不代表 DOI 失效**；要判有效性得看 `doi.org` 的落地码。
13. **arXiv export API 返回 0 字节 = 取数失败，不是零命中**。**必须做阴性对照**（用确定不存在的词）才能下结论。
14. **子代理的"指控"要逐字复核**（本会话核了 5 篇落地页）；**但子代理提出的、我没想到的正文缺陷，往往是对的**
    （§6(b) 列名写反、§2 对自己引文的错误概括，都是代理发现的）。
15. **"未找到"只能写成"在本次可达通道与检索式下未找到"**，并附检索式原文与通道状态。
16. **摘要数字/引用的"存在性"检查要双向做**（定义了没引 / 引了没定义）。

### 7.3 文档类

17. **英文稿里手滑留中文字**（本会话在 §4.4 留了个"量"）⇒ 改完英文稿**必扫 CJK**。
18. **cover letter / 待办清单 / 核验件都可能是"旧稿时代"的**——用之前先问"它描述的是哪一版稿子"。
