# G1 test 口径裁定（2026-10-04）

## 裁定

**G1 的 test/评估口径：四个格统一用各自 yaml 自带的 `images/val`。**
（DOTA15：`dota15_yolo/images/val`，458 张；AI-TOD：`AI-TOD_yolo/images/val`，2,804 张。）

**不用** `carve_aitod20/images`（1,000 张）。

## 依据（三条，其中第一条是决定性的）

| # | 依据 |
|---|---|
| **1** | ★ **carve 与 50p 训练集从定义上就冲突**：`carve_aitod20 = 池 − 20p训练集`，而 `train_aitod_50p`（5,607 张）**也从池里抽** ⇒ `carve ∩ 50p训练 ≠ ∅` **几乎必然**。把 carve 设为评估集，就等于让 50p 的评估图**有一部分是它训练过的** ⇒ 从定义上排除。 |
| 2 | **与冻结设计一致**：G1 四个格的 yaml 本来就是 `val`/`test` 都指 `images/val`。 |
| 3 | **单一共享评估面**：四格同一评估集 ⇒ 域差档与预算档的比较**不被"换了评估集"污染**。 |

## ★ 前置核查：训练/评估重叠（**已实测，两机一致**）

在裁定前先确认"50p 训练是否撞了 `images/val`"——若撞，问题就不在选口径而在划分方式。

| 集合 | 张数 | 与 `images/val` 交集 |
|---|---:|---:|
| `dota15 train/10_percent` | 141 | **0** |
| `dota15 train/20_percent` | 282 | **0** |
| `dota15 train/30_percent` | 423 | **0** |
| `dota15 train/40_percent` | 564 | **0** |
| `dota15 train/50_percent` | 706 | **0** |
| `aitod images/train_aitod_10p` | 1,121 | **0** |
| `aitod images/train_aitod_20p` | 2,243 | **0** |
| `aitod images/train_aitod_50p` | 5,607 | **0** |
| **REF** `aitod images/train`（全池） | 11,214 | **0** |
| **REF** `aitod carve_aitod20` | 1,000 | **0** |

⇒ **四个格都无重叠**；**AI-TOD 的 `images/val` 与整个池都不相交** ⇒ val 是**真留出**，
50p 从池里抽**不可能**泄漏 val 图（连"原则上可能"都不成立）。
⇒ **预算对比（10p vs 50p）未被训练/评估重叠污染。**

★ 这条核查**否掉了我原本担心的共变**：我曾担心我从池里补 50p 会含 val 图；实测池本身与 val 不相交，故不成立。

## 已知的评估面事实（如实登记，不隐藏）

1. **DOTA15 的 `val` 与 `test` 是同一个 458 张集合**（`dota15_*p.yaml` 里两行都指 `images/val`）
   —— 所以 c1/c2 的"test"与"val"**同义**，不构成"另有一套留出"。
2. **AI-TOD 的 `val` 与 `test` 也是同一个 2,804 张集合**（`aitod_10p/50p.yaml` 同理），
   但 AI-TOD **另有** `carve_aitod20` 的 3-way 版本用 carve 作 val —— 两套协议存在，**G1 用前者**（见依据 1）。
3. **`dota15_50p` 实际训练 705 张**（706 中 `P0334` 因坐标越界被 ultralytics 丢弃）；
   两臂同集合 ⇒ 不影响配对。

## 实施

`results.csv` **只有 val 指标**（`metrics/mAP50-95(B)`），**没有 test 列**。因此"test 口径 = `images/val`"
意味着：**判读即用 `results.csv` 里的 val 列**，口径与上文一致，**无需另跑评估**。

⇒ 这同时**解掉了那个缺口**：原先的缺口感来自"注册判据写 test、results.csv 只有 val"，
而既然 `val` 与 `test` 在 G1 的 yaml 里指同一集合，**val 列就是 test 读数**。
（**但必须在稿内/表内声明这一等价**，不能让读者以为另有一套 test 留出。）
