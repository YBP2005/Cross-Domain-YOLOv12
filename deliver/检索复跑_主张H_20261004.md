### 1.1 通道自身的方法学发现（影响检索式设计，务必记录）

1. **arXiv API 的 `abs:"多词短语"` / `all:"多词短语"` 查询不按预期工作**：`abs:"annotation density"`、`abs:"instances per image"`、`abs:"small object" AND abs:"domain gap"`、`abs:"dataset statistics" AND abs:transfer` 等查询均返回 **200 且 14k–23k 字节**，但条目是 2020-12 的粒子物理 / 交通流 / 图论论文——即**与检索式无关的"最近提交"清单**，属**伪命中**。若只看"字节数大"就会误判为"有命中"。因此这些条目**不计入任何候选**。
2. 与之相对，**不带引号的多词合取式**才给出语义相关的排序结果（例：`domain adaptive object detection` → 200/18,568B/8 条 DAOD 真命中）。
3. **零命中与限流的区分**：零命中 = HTTP 200 且 **758–792 字节**（无 `<entry>`）；限流 = **HTTP 429 且 bytes=1**。二者绝不可混记。
4. 限流是**并发造成**的（父代理同机复测连续三次 200 可证），非通道损坏；退避 25s、间隔 5–6s 后本代理亦稳定取得 200。

## 4. 最接近的一篇 + 判词

**最接近：Tran, Nguyen & Hassner, 2019, _Transferability and Hardness of Supervised Classification Tasks_, ICCV 2019（DOI 10.1109/ICCV.2019.00148；arXiv:1908.08142）。**

判词：(1) 它与主张 H 共享**同一命题形状**——"用**任务自带标注的统计量**、**不训练模型**地预测**迁移难度/迁移损失**"，其摘要明言"treating training labels as random variables and exploring their statistics"、"this value is related to the loss of the transferred model"，并给出 437 个分类任务上的强相关验证。(2) 但它把统计量取为**源任务与目标任务标签分配之间的条件熵**，属**任务对层面的信息论量**，而主张 H 的调节变量是**单语料层面的"每图实例数"**，是一个可直接从标注文件数出来的计数密度；二者不是同一个测量。(3) 它的因变量是**迁移损失与任务硬度**（连续难度），主张 H 的因变量是**增益的符号**（正负），后者在语义上是"迁移是否反而有害"，Tran et al. 并未考察符号翻转，也未处理负迁移。(4) 其评测域是**图像分类**（人脸属性、动物属性、鸟类细粒度），主张 H 的九语料是**目标检测**（含 dota15 / visdrone 的密集小目标航拍与 neu_det 的工业缺陷），密集场景下的实例密度在该文中根本没有对应物。(5) Kornblith et al. 2019 虽更著名，但它预测迁移性能用的是**源模型**的 ImageNet 精度，自变量轴与主张 H 正交，不构成对"**目标语料**属性作调节变量"的覆盖。(6) 因此：**Tran et al. 2019 是可引用的最近先例与"同层"对照，但不构成对主张 H 的新颖性威胁**；主张 H 的可辩护增量在于"目标域标注密度（每图实例数）作为增益**符号**的**候选**调节变量"这一具体测量与因变量，以及作者已自陈的"密度与 pair 混淆、故仅为候选"的克制表述。(7) 需要提醒的风险点是：主张 H 的自变量是**语料级 n=9 的相关（r≈0.34）**且与 pair 混淆，审稿人很可能要求引用 Tran et al. 2019 与 Kornblith et al. 2019，并把 H 的定位从"首次发现"降级为"在检测与'目标域标注密度'这一具体轴上的延续性观察"。

## 5. 证据强度声明

- **可达通道数**：4 个可用（Crossref、arXiv API、OpenAlex、arXiv 落地页），2 个不可用（Semantic Scholar Graph API 无 key = HTTP 429；dblp API = Anubis 反爬挑战页）。共 **79 条互异检索式 / 80 次通道调用**。
- **通道是否退化**：arXiv API 在本代理运行期间**间歇性限流**（HTTP 429，bytes=1），共 3 条检索式受影响；其中 2 条经 25s 退避重试后**仍**为 429，故这 2 条（`instance density domain adaptation detection`、`object density transfer difficulty detection`）**按"失败待重试/无结果"记录，未按"零命中"记录**。其余检索式在 sleep 5–6s 节流下稳定取得 HTTP 200。**Crossref 与 OpenAlex 全程无失败**（除被明确标注的 S2/dblp 外）。
- **一处必须声明的工具偏差**：arXiv API 对 `abs:"…"`/`all:"…"` 引号短语查询返回**伪命中**（无关的"最近提交"清单，14k–23k 字节）。本次已将 7 条此类查询**作废处理**（见 2.1 第 16–22 行），其条目未进入候选表。这意味着 arXiv 侧的"零命中/无先例"结论，**只在"不带引号的多词合取式"这一检索形态下成立**。
- **结论的措辞边界**：本报告的全部阴性结论均应读作 **"在这些通道（Crossref / arXiv API / OpenAlex）与这些措辞下未找到"**，**不是**"该工作不存在"。尤其：**Semantic Scholar 与 dblp 两通道本次完全不可用**，而它们恰是 DAOD 与检测类预印本覆盖率最高的两个通道；arXiv 又有 3 条检索式因限流未能完成。若要把主张 H 的"无同层先例"作为正式的新颖性依据，**应在通道空闲时补跑 arXiv + Semantic Scholar（或带 key）**并补做引文网络追踪（例如沿 Tran et al. 2019 与 Yu et al. 2026 的引文/被引）。
- **取证纪律**：候选表中所有引号内文字均来自本次实际取回的响应体（arXiv API `<summary>` 或落地页 `citation_abstract`）；Crossref/OpenAlex 仅提供元数据的两条已明确标注"未取回摘要正文，故不引句"。
