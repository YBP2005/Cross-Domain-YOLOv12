## 一、损失轴：补"换损失后的**增益**"（现有数据缺 `{loss}-lr005` 臂）

要回答的是：**把微调损失换掉，`lr005 − base` 这个增益还在不在**。
这需要每个种子下**四格齐全**：`shapeiou-base` / `shapeiou-lr005` / `{loss}-base` / `{loss}-lr005`。

选格原则：挑**三方划分协议**（`*_3way.yaml`）的格优先 —— 它是全稿最干净的口径；
替代损失挑该格 **base 臂覆盖最好**的那一种。

## 二、架构轴：同目标、同 COCO 起点、只换 backbone

为什么现在做不到：**预训练权重决定 backbone** ⇒ backbone 与 (配对, 族) 完全共线，
格内不可能出现两种 backbone。

底座的现状（已实测）：

| 组合 | 现状 |
|---|---|
| `yolo11n.pt → dota15_20p_3way`（族 `r15`） | **base 3 种子 + lr005 3 种子**（其余是 `_PARTIAL_`，按铁律 18 不算独立种子）|
| `yolo12n.pt → dota15_20p_3way` | **不存在** |

⇒ 补 `yolo12n.pt → dota15_20p_3way` 并把两边都推到目标 n，即得**同目标、同为 COCO 起点、
同三方划分、同预算**下的纯架构对照 —— 比 §4.4 现在的"第二个 (源域, backbone) 组合"干净得多。

## 三、★ 对照怎么定义（两组实验的**统计口径**）

### 3.1 损失轴 —— **同格四象限**

对每个种子 s，四个量同格（同配对/同族/同轮数/同预训练）齐备：

```
增益_shapeiou(s) = lr005@shapeiou(s) − base@shapeiou(s)
增益_loss(s)     = lr005@{loss}(s)   − base@{loss}(s)          # 本实验补出来的
Δ_loss(s)        = 增益_loss(s) − 增益_shapeiou(s)             # 逐种子配对
```

**判据**（用论文自己的闸门）：`Δ_loss` 在 n≥10、或 n≥5 且逐种子全同号、或 |t|≥4 时可报方向；
否则**只报均值与区间，不报方向**。
★ 逐种子配对是必须的：不同臂的种子集若不同，均值相减会混入种子效应。

### 3.2 架构轴 —— **跨格、逐种子配对**（不是格内对照）

⚠ **必须写明**：本对照**不可能**是格内对照 —— 预训练权重决定 backbone，
所以 backbone 永远与 `pair` 共线，格内**永远**只会有一种 backbone（A12 的实测：0 格）。

正确的对照定义是**跨格**，两格只差 backbone：

| | 格 A | 格 B |
|---|---|---|
| pair | `yolo11n→dota15` | `yolo12n→dota15` |
| family | `r15` | `r15` |
| 预算 / 轮数 | 20% / 100ep | 20% / 100ep |
| 协议 | `dota15_20p_3way.yaml` | `dota15_20p_3way.yaml` |
| 种子 | s42–s\{N\} | **同一组** s42–s\{N\} |

```
Δ_arch(s) = 增益_y12(s) − 增益_y11(s)        # 逐种子配对
```

★ 两边都是 **COCO 起点**（无源域预训练）⇒ 架构是**唯一变量**，
这比 §4.4 现在那个"第二个 (源域, backbone) 组合"干净得多。
★ 但也要写明**它失去了什么**：这是"COCO→目标"的迁移，**不含源域预训练**那一环，
所以它能回答"增益是否依赖 backbone"，**不能**回答"增益是否依赖源域预训练"。

## 四、密度轴（**可选**，需先造数据集 —— 与上面两组不是一回事）

密度与配对共线（每个 corpus 对应固定配对），且底座里**没有**同语料的密度变体
（`budget_pct` 是标注比例，**不是**密度）⇒ 这条**要造数据**，不是补 run 就行。

**设计（若要做）**：拿一个密集目标域，按"每图实例数"子采样出 2 个更稀的变体，
其余全固定：

| 项 | 设定 |
|---|---|
| 固定 | 源域预训练权重、目标语料、标注预算、轮数、臂、种子集、三方划分 |
| 变 | **目标集的每图实例数**（`inst/img`）：原样（密集） / 子采样一档 / 子采样两档 |
| 每档 run 数 | 2 臂 × n 种子 |
| n=10 时合计 | **2 档 × 2 臂 × 10 = 40 run**（密集那档已有） |

★ 子采样规则必须**确定且记录**（保留哪些图、按什么阈值），否则不可复现；
★ 子采样会同时改变**图数**，而图数与预算共线 ⇒ 必须**同时固定图数**（按图数下采样后再比），
   否则测到的是"图数效应"不是"密度效应"。**这一点决定了该实验的设计难度，建议单独评估后再决定做不做。**

## 五点九、续跑 / 中断处理（照此做，别乱来）

1. **不要覆盖正在运行的脚本**：bash 是**边读边执行**的 —— 往正在跑的 `_supp_*.sh` 上写，
   会读出半个文件。脚本一旦启动就不要再改它；要改先停队列。
2. **停队列**：只杀队列包装那个进程（形如 `bash _supp_A_gpu0.sh`），
   **别杀 `train_obj.py` 本身**，否则当前那条会变成 `.incomplete` 中断件。等当前 run 自然结束再停更稳。
3. **续跑**：把修好的脚本重新上传，再执行同一个脚本 —— 每条都带
   `if [ -d /workspace/runs/<name> ]; then SKIP; fi`，**已完成的不会重做**。
4. ⚠ **`flock` 单实例守卫**：旧实例没退干净时新实例会直接 `exit 0`（日志只一行）。
   先确认 `pgrep -af bash _supp` 为空，再启动。
5. ⚠ **不要**按 `flock` 关键字 pkill —— 会误杀其它合法锁。

> **已知无害瑕疵**：本批启动脚本里写的是 `date -u +%F %T`，shell 会把 `%T` 当成
> 第二个操作数，`date` 报错 ⇒ 日志时间戳显示为 `[]`。**只影响日志可读性，不影响训练**。
> 生成器已改用 `ts()` 包装（输出 ISO8601）；**续跑时换上修好的脚本**即可。
